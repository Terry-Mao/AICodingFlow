# 产品变更报告：2026-05-26 至 2026-05-27

扫描窗口：`2026-05-26T00:00:00Z`（含）至 `2026-05-28T00:00:00Z`（不含）。

## 用户可见变更

- 仓库级 agent 指令已移动到根目录 `AGENTS.md`，让 Codex 默认加载同一份仓库约定；同时新增根目录 `CLAUDE.md` 指向 `AGENTS.md`，供 Claude Code 复用相同指令。来源：PR #175，commit `0a722ec194ab29be69d073bcf274fe3d8a7f5102`。
- 仓库级说明被精简为只保留仓库地图、验证命令和跨 workflow 约定，并明确 agent 生成的 issue、PR、commit summary、spec 和 workflow metadata 默认使用中文。来源：PR #176，commit `efaf23e05c5367e867b4a2323121a0a0df1c8e8e`。

## Bug fixes

- 修复 product change report workflow 在没有可报告内容时仍创建空报告 PR 的问题。现在 workflow 会识别缺失、空白或整篇“无变化”占位报告，并将对应 PR 记录为 `scanned_no_update`，避免更新 ledger 或创建无效报告 PR。来源：PR #168，commit `be732598e7f85633752ba1b87382a7b1aae57280`。
- 修复 product change report、dedupe guidance 和 PR review guidance 三类自动化在更新 workflow PR 时可能命中已关闭 PR 的问题。workflow 现在只查找 open PR，再决定编辑现有 PR 或新建 PR。来源：PR #173，commit `d47e02d4f21a71d209f64741d0610394ea58b268`。

## 行为变更

- Product change report 支持手动历史回填：workflow dispatch 可传入 `start_date` 和 `end_date`，并生成区间命名报告，例如 `docs/updates/auto-update-2026-05-09-to-2026-05-26.md`。来源：PR #168。
- Product change report 的扫描窗口改为逐 UTC 日期查询 merged PR，并在拉取 PR 详情后再次校验 `mergedAt` 是否落在窗口内，减少边界日期和 GitHub Search 查询语义带来的误报风险。来源：PR #168。
- Product change report ledger 条目新增 `status`，可区分 `reported` 与 `scanned_no_update`，从而记录已扫描但无需报告的 PR，避免后续重复处理。来源：PR #168。
- 语言偏好从单个 skill 或 workflow prompt 中移出，集中到仓库级 agent 指令管理；最终规则要求默认人类可读输出使用中文，同时保留代码标识符、路径、标签、命令和引用输出不变。来源：PR #172，Refs #170。

## 内部工程变更

- 新增 `.github/scripts/check_product_change_report_status.py`，用于在 ledger 更新和 PR 创建前分类生成报告状态，并补充了空报告、无变化占位、历史区间、ledger status 和 workflow gating 的回归测试。来源：PR #168。
- `.gitignore` 补齐 workflow handoff 文件忽略规则，包括 `issue_context.json`、`issue_comments.txt`、`pr-metadata.json`、`validation-output.txt`、`validation-error.txt` 和 `branch-start-shas.json` 等临时产物。来源：PR #176。

## 风险或待验证

- Product change report workflow 现在同时覆盖“生成报告”和“扫描但无报告”两种 ledger 状态，后续 scheduled run 应确认 `scanned_no_update` 记录不会掩盖后来需要补写的真实报告。来源：PR #168。
- 语言偏好在 2026-05-27 经 PR #171 添加到 product-change-report skill 后，又在 PR #172 集中到仓库级指令并移除 workflow 覆盖。后续自动化应以根目录 `AGENTS.md` 为准，避免旧 prompt 或旧 skill 片段重新引入分散规则。来源：PR #171、PR #172。

## 可能需要同步的长期文档

- 如果维护者希望外部贡献者理解 product change report 的历史回填、空报告抑制和 ledger status 语义，可以将这些运维行为补充到长期 contributor 或 workflow 文档中。来源：PR #168。
- 如果仓库同时面向 Codex 和 Claude Code 使用，长期文档可说明根目录 `AGENTS.md` 与 `CLAUDE.md` 的加载关系，以及默认中文输出约定。来源：PR #175、PR #176。
